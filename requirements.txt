# Transitive pin (not imported by our code).
# sqlparse arrives with Django (Django requires sqlparse>=0.3.1). Versions
# <= 0.5.6.dev0 carry three high-severity DoS advisories (ReDoS on
# dollar-quoted literals, O(subtree) materialisation in TokenList.__init__,
# quadratic group_comments) plus one medium (backslash escaping in generated
# snippets). 0.6.0 is the first patched release.
#
# Reachability (DRF-1394): none of those paths run on the pilot. Django only
# calls sqlparse from BaseDatabaseOperations.prepare_sql_script (RunSQL
# migrations), the mysql/sqlite3 introspection backends, and the --debug-sql
# test runner. The postgresql backend overrides prepare_sql_script to
# `return [sql]`, dev/prod/test all run postgresql, we have zero RunSQL
# migrations, and we run pytest-django rather than Django's test runner.
# Pinned anyway because the bump costs nothing (we never import it) and it
# clears all three highs so the next real high is not buried under them.

# Repo: https://github.com/AndreyDeveloper84/ayla-ai-core (private)
#
# Pinned SHA aligned with bot-platform pyproject.toml. Both services
# share the same SHA so prompt rendering, tool dispatch, history
# truncation, and safety behaviour stay identical across channels
# (codex P0-5). The A9 follow-up that landed this SHA also rewired
# ai/concierge_factory.to_core_specialist_context() to thread the
# new required tenant_id kwarg through; AIChatView resolves the id
# from request.tenant (TenantContextMiddleware) and falls back to
# the GLOBAL_TENANT_SENTINEL when no tenant context is set.
#
# Bump procedure:
#   1. Land the change in ayla-ai-core, tag vX.Y.Z.
#   2. Capture target SHA: `cd ~/PycharmProjects/ayla-ai-core && git rev-parse vX.Y.Z`.
#   3. Update BOTH this line AND bot-platform pyproject.toml in coordinated PRs.
#   4. PR title: `chore(deps): bump ayla-ai-core <prev> → vX.Y.Z (SHA <short>)`.
#
# CI auth: this is a private repo. The runner needs read access via either
#   (a) deploy key on the repo + GIT_SSH_COMMAND with the key, or
#   (b) a personal access token: https://${GH_TOKEN}@github.com/...
# Local dev: `pip install -e ../../ayla-ai-core` keeps a faster iteration loop;
# the editable install satisfies the same requirement.
#
# DRF-1441 — realigned f773e7d → d72a5de (main tip). Three library
# commits sit in that gap, all three in memory.py:
#   af620ba — `sources=` kwarg: a fact the system inferred renders in its
#     own section instead of passing for something the client said. This is
#     the consumer side of the `data_sources` map this backend already
#     serves from users/internal_personal_context_api.py; additive, and the
#     output is byte-identical when the kwarg is omitted.
#   ee6425a — price_range_min/max had no declared priority, so the budget
#     line sorted to the tail and fell off the max_facts=8 cut on a full
#     profile. The backend serves exactly such profiles to the bot; see
#     users/tests/test_memory_erasure_matrix.py::
#     TestBotPromptRendererPin for the guard that pins the fixed order.
#   d72a5de — DRF-1443. af620ba treated ONLY the exact string "inferred" as
#     derived, but the provenance vocabulary is written by three repos and
#     had already diverged: this backend stamps "explicit" for stated, its
#     internal PATCH accepts behavioral / conversational / transactional,
#     the nightly pass writes "inferred", and erasure writes "erased". So a
#     field this backend marked "behavioral" reached the prompt looking like
#     the client's own words. The rule is now closed on the quote side —
#     STATED_SOURCES ("stated" | "explicit") is a quote, anything else
#     including a value the library does not know is derived. The backend's
#     data_sources map can be passed straight through, unnormalised.
# None of the three commits touches anything this repo imports in production
# (AIConcierge, render_system_prompt, SpecialistContext, the tool layer),
# so no call site changed with this bump.
