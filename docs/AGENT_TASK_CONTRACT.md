# Ayla Agent Task Contract

## Назначение

Операционный контракт между оркестратором и агентом-исполнителем (окном).
Любое задание агенту оформляется по этому стандарту: он убирает
двусмысленность, ограничивает самодеятельность и делает результат
проверяемым.

Два варианта применения:

- **Полный промпт нового окна** — все разделы 0–9 (агент ничего не знает
  о проекте).
- **Follow-up для работающего окна** — разделы 1–8 (РЕШЕНИЕ, КАНОНИЗАЦИЯ,
  SCOPE, DoD, ЗАПРЕТЫ, ТЕСТЫ, КОММИТ, ОТЧЁТ).

## 0. КОНТЕКСТ

- Task/issue:
- Репозиторий:
- Рабочая ветка:
- Базовая ветка и ожидаемый SHA:
- Владелец зоны:
- Зависимости:
- Прочитать перед работой (нормативные документы):

## 1. РЕШЕНИЕ

- Однозначный GO / NO-GO / выбранный вариант.
- AMD/DEC/issue, на основании которого принято решение.
- Что именно считается утверждённым.

## 2. КАНОНИЗАЦИЯ

- Кто обновляет контракт, ADR или Decision Log.
- Где находится нормативный документ.
- Блокирует ли отсутствие документа начало кодирования.
- Как действовать, если документ ещё не появился в checkout
  (использовать сообщение оркестратора как явное решение, отметить
  отсутствие в отчёте).

## 3. SCOPE

### 3.1 Что изменить

- модули, файлы или допустимые директории;
- модели/миграции;
- поведение;
- интеграционные точки.

### 3.2 Инварианты

- что обязано происходить;
- что никогда не должно происходить;
- порядок обработки;
- требования идемпотентности и tenant isolation.

### 3.3 Что не входит

- соседние функции;
- будущие улучшения;
- чужие модули;
- инфраструктурные действия вне задания.

## 4. DEFINITION OF DONE

- Функциональный результат.
- Миграции (если требуются).
- Новые и существующие тесты зелёные; полный прогон зелёный.
- Совместимость с контрактами.
- Отсутствие изменений вне scope.
- Commit и отчёт подготовлены.

## 5. ЗАПРЕТЫ И СТОП-УСЛОВИЯ

Права по заданию фиксируются явно:

```
Commit: разрешён.
Push своей ветки: разрешён/запрещён (по заданию).
Merge: запрещён (исполняет оркестратор).
Deploy: запрещён (исполняет оркестратор).
Feature gates: запрещены (решение оркестратора).
```

- Не менять чужие зоны (таблица владения в owning-документе).
- Не придумывать поля, события, endpoints вне контракта.
- Не читать и не выводить секреты (только имена переменных).
- Не исправлять unrelated failures молча.

**СТОП-УСЛОВИЯ:**

- найден конфликт с AMD/DEC/контрактом;
- требуется изменить чужой модуль;
- обнаружена незаявленная миграционная зависимость;
- рабочее дерево содержит пересекающиеся чужие изменения;
- необходим новый endpoint/event/payload field вне контракта;
- полный прогон выявил unrelated baseline failure;
- выполнение требует merge, push, deploy или включения gate.

**При стоп-условии:**

- откатить только свои незакоммиченные спорные изменения;
- не удалять и не откатывать чужие изменения;
- продолжить независимую часть задачи, если возможно;
- передать оркестратору факт, варианты и рекомендацию.

## 6. ТЕСТЫ

Новые обязательные тесты (по номерам):
1. …
2. …

Регрессионные наборы: …

Полная команда: …

Ожидаемый результат: количество/статус; допустимые baseline failures и
их документирование.

## 7. ПЕРЕД КОММИТОМ

- git status чистое от постороннего.
- diff и список файлов — только в scope.
- Секреты и временные файлы не в diff.
- Миграции и их конфликты проверены.
- Точечные тесты пройдены.
- Полный прогон пройден.
- lint/type-check пройден.
- Unrelated failures зафиксированы отдельно.

## 8. КОММИТ

- Conventional commit: `type(scope): description`.
- Один логически целостный commit либо явно заданное разбиение.
- Merge/push — только если разрешены заданием явно.

## 9. ОТЧЁТ

1. Ветка и commit SHA.
2. Что реализовано.
3. Изменённые файлы.
4. Миграции.
5. Новые тесты.
6. Результат точечных тестов.
7. Результат полного прогона и lint/type-check.
8. Расхождения с контрактами.
9. Блокеры и оставшиеся решения.
10. Подтверждение соблюдения запретов.
11. Что должен сделать оркестратор дальше: merge, gate, deploy, replay.

## Прецедент

Эталон применения — задание `feat(eventbus): support booking no-show events`
(2026-07-20, AMD-018): scope по номерам, явный запрет денежных действий,
явный запрет трогать delivery gate, 6 обязательных тестов, отчёт по пунктам.
