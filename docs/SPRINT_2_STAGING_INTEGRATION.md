# Спринт 2 — Staging Integration (2026-07-20 → 2026-07-27)

Статус: подготовлен 2026-07-19, старт — после закрытия батчей спринта 1 (W1-C7, W3-followup2, W4-2b, W6-wave3).
Владелец: оркестратор. Трекер готовности: `docs/qa/PILOT_PROGRESS.md`.

## Цель спринта

Сквозной путь пилота работает на staging **end-to-end с реальными данными**:
сообщение боту → подбор мастера → запись через Ayla REST (флип #1041 ON) →
онлайн-оплата тестовой картой → напоминание T−24h → memory-ask → события в обе
стороны → начисление 90₽ мастеру/платформе.

## Definition of Done (спринт закрыт, когда)

1. Флип `BOOKING_VIA_AYLA_REST` включён на staging (покрытие каталога 100%).
2. Smoke-runner W6: 7/7 сценариев зелёные на staging (booking CRUD, memory-ask,
   billing charge, eventbus round-trip, C5 dual-delete, R1, UX-пробы).
3. Деньги: hold → capture → split 90₽ прошли на тестовом магазине ЮKassa;
   подписка мастера списана; dunning-дрель до блокировки записи.
4. Память: memory-ask работает на staging (consent → вопрос → PATCH → в блоке
   промпта).
5. Runbook отрепетирован (rollback-дрель пройдена).
6. ≥10 мастеров готовы к пилоту (KYC пройдено, расписание/услуги наполнены).

## Риски

1. **Staging не существует** — главный блокер; решается день 1, иначе весь спринт сдвигается.
2. **KYC мастеров** — самая длинная операционная цепь (дни на мастера); стартовать немедленно, не ждать стенда.
3. **Тестовый магазин ЮKassa** — задержка доступов блокирует S3 целиком.
4. **Данные Пензы**: реальные услуги/расписание пилотного салона — без них link coverage формальный.
