## E1 — Staging-инфраструктура

**Вопрос:** `dev.gobeauty.site` — это действующий staging или нужен новый стенд?
Где поднимать bot staging (ai-bot-platform) — тот же VPS?

**Что нужно от владельца:**
1. Подтвердить, что `dev.gobeauty.site` — staging Ayla backend (состояние, доступы).
2. Решение по bot staging: тот же VPS (отдельный compose/порты) или отдельный хост.
3. Доступы: SSH/деплой-процесс (deploy.sh), где лежат env-файлы.

**Блокирует:** весь спринт 2 (S0–S6): прогон link coverage, round-trip событий,
деньги на staging, smoke-runner, rehearsal.
**Fallback:** один VPS с docker-compose обоих backend (минимум), staging-флаг.

## E2 — Тестовый магазин ЮKassa

**Вопрос:** есть ли тестовый магазин ЮKassa (shopId + secret key для тестовых
платежей)? Если нет — регистрируем сейчас (это минуты в кабинете ЮKassa).

**Что нужно:**
1. shopId + secret key тестового магазина (в env staging, не в код).
2. Доступ в кабинет ЮKassa — для настройки webhook URLs (2 шт.):
   - payments: `https://<ayla-staging>/api/v1/payments/webhook/`
   - billing: `https://<ayla-staging>/api/v1/internal/billing/webhook/` (AMD-014)
3. Тестовая карта (номер из документации ЮKassa — для smoke).

**Блокирует:** S3 (деньги на staging: hold→capture→split, подписка, dunning).

## E3 — MAX staging-бот

**Вопрос:** есть ли тестовый MAX-бот (токен) для staging, или создаём нового?
Также: staging Mini App URL — регистрировать отдельно?

**Что нужно:**
1. `MAX_BOT_TOKEN` staging-бота (в env bot staging).
2. Решение: тот же бот с test-окружением или отдельный staging-бот.
3. `MAX_MINIAPP_URL` для staging (webview URL miniapp на staging).

**Блокирует:** E2E-сценарии через канал (запись/напоминания/memory-ask в DM),
smoke 5–7.

## E4 — Список пилотных мастеров (15+)

**Вопрос:** кто конкретно из мастеров «Формулы тела» (или вне его) идёт в пилот
Пензы? Нужен именованный список ≥15.

**Что нужно:**
1. Список: имя, специализация (услуги), контакт, статус согласия.
2. Для каждого — данные для KYC в ЮKassa (паспорт/ИНН/реквизиты по форме
   самозанятого или ИП) — процесс на 3–5 дней на мастера, старт немедленно.
3. Назначить ответственного за онбординг (кто звонит/сопровождает).

**Блокирует:** supply пилота (без мастеров пилот пустой), link coverage по
реальным услугам, S5.1 спринта 2, метрики пилота (≥50 мастеров к M4).
