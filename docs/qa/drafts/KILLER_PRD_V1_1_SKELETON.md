## 0. Назначение и дельта v1.0 → v1.1

v1.0 операционализировал цепочку «Завтрак → Дефицит → Запись → Прогресс» с пищевым триггером в центре.
**v1.1 смещает центр на память** (AYLA-DEC-0002):

| Аспект | v1.0 | v1.1 |
|---|---|---|
| Центр сценария | еда → beauty цепочка | **память: «Ayla помнит и понимает меня»** |
| Еда → beauty | ядро | один из триггеров (первый внешний вход в память) |
| Обоснование moat | «никто не строит AI-компаньона с памятью» | booking = commodity (YCLIENTS ~90% сетевых, DIKIDI); защищаемый ров — накопленный контекст; окно гонки 12–18 мес |
| Канал | Telegram + Mini App | **MAX-бот + MAX Mini App** (AYLA-DEC-0004) |
| Горизонт | MVP phases | **пилот 2026-08-15, Пенза** (AYLA-DEC-0003) |
| Оплата | YooKassa обязательна в флоу | опциональна (AYLA-DEC-0006); деньги мастера — D1/D7/D8 |
| North Star | % пользователей с killer moment / нед | **[TBD владельцу]** memory-driven North Star (§3) |

## 1. Problem Statement (skeleton)

- 1.1. Booking-функциональность — товарный рынок: YCLIENTS ~90% сетевых, DIKIDI; фича «записаться» не создаёт удержания.
- 1.2. Пользователь повторяет контекст каждому инструменту/мастеру заново (аллергии, предпочтения, бюджет, любимый мастер) — когнитивная нагрузка (Constitution ст. I).
- 1.3. Без памяти Ayla = «ещё один канал записи»; с памятью — единственный продукт, который «знает меня» между доменами (еда, уход, записи).
- 1.4. Доказательства: [TBD] интервью (v1.0 требовал 5+ до Sprint 1 — статус?), Research Synthesis (окно 12–18 мес).

## 2. Killer Scenario v1.1 — «Ayla помнит и понимает меня» (skeleton)

**Нарратив (проект, требует редактуры владельца):**
> Пользователь в MAX-боте упоминает, что кожа реагирует на новый крем. Ayla спрашивает ровно один
> уточняющий вопрос (и только потому, что ответ нельзя получить иначе — ст. VI). Через неделю,
> подбирая процедуру, Ayla учитывает это без повторных расспросов: «с учётом реакции на крем —
> вот безопасный вариант у твоего мастера Анны, завтра 19:00». Запись — два тапа. За день до
> визита — напоминание. После визита Ayla помнит результат для следующей рекомендации.

**Декомпозиция (operational view, проект):**

| # | Шаг | Пользователь | Ayla | Capability | Статус пилота |
|---|---|---|---|---|---|
| M1 | Триггер | пишет в MAX-бот (или сканирует еду — триггер из v1.0) | распознаёт потенциальный факт | intent/router + consent-гейт | 🟡 |
| M2 | Минимальный вопрос | отвечает (или отказывается) | `should_ask` → один вопрос; `skip` при отказе | memory-ask (source 1) | ❌ wiring (W5) |
| M3 | Сохранение | — | факт сохранён с источником + confidence + consent-scope | UserPersonalContext / MemoryEntry | ✅ |
| M4 | Использование | получает рекомендацию | memory-блок в промпте (ai-core v0.9.0), факт виден в объяснении | build_memory_block + composer | 🟡 |
| M5 | Действие | 2 тапа → запись | booking через Ayla REST; оплата опциональна | booking REST | ✅ |
| M6 | Сопровождение | получает T−24h | напоминание (R1) | reminders | ✅ |
| M7 | Обратная связь | подтверждает/исправляет/удаляет | вето > гипотезы (ст. VII); факты редактируемы | экран «Мои данные» + forget | 🟡 (C5) |

**Триггеры (внешние входы в память), приоритет пилота:** 1) DM-диалог (memory-ask) — критпуть;
2) еда → beauty (v1.0 flow, как готова цепочка); 3) повторные записи (поведенческие гипотезы — только как гипотезы, ст. VII).

## 3. Goals & Success Metrics (skeleton)

- Goals: (G1) доказать, что память создаёт видимую ценность; (G2) накопление контекста = retention; (G3) memory-driven записи растут с возрастом аккаунта.
- North Star [TBD владельцу]: кандидат W6 — **% рекомендаций, принятых пользователем, где явно использован ≥1 факт памяти** (или сохранить «killer moment/нед» с переопределением под M1–M7).
- Метрики пилота (из acceptance §10.7 + v1.0 §3.2, адаптировать): memory enrichment rate; answer rate на should_ask; skip rate; % рекомендаций с memory-блоком; конверсия рекомендация → запись с/без памяти (A/B по наличию фактов); качество фактов (manual QA-выборка, целевое ≥85%).
- Метрики-ограничители (ст. X): частота проактивных вопросов ≤ [TBD]; complaint rate на «навязчивость».

## 6. Solution Overview (skeleton)

- 6.1. Архитектура: MAX-бот + MAX Mini App → ai-bot-platform → Ayla REST; ai-core v0.9.0 (memory block); billing-контур вне killer-скопа (связь только через C1-гейт и экран долга мастера).
- 6.2. **Memory Model v1.1** — ядро PRD: зоны (green пилот), источники, confidence, TTL, удаление — **выносится в отдельный канон: Memory Lifecycle spec** (черновик `docs/qa/drafts/MEMORY_LIFECYCLE_SPEC.md` → ayla-knowledge). В PRD остаётся product-view: какие классы фактов видит пользователь и как редактирует.
- 6.3. Insight Engine: rules-based v0.1 (как v1.0), правила ревьюит legal; триггеры расширить с питания на beauty-history [TBD: список правил пилота].
- 6.4. Recommendation Composer: top-1 (не список); объяснение «почему» со ссылкой на факт (ст. VII); экономическая нейтральность (ст. IV — платный статус мастера НЕ влияет на ранжирование).
- 6.5. Consent UX: memory_green consent; отказ не блокирует базовые функции (ст. XIV).

## 7. User Stories & Acceptance Criteria (skeleton, P0 = пилот)

- **M-01** (соотв. §10.7): вопрос → ответ → сохранено → следующая рекомендация учла; consent-гейт (без consent — молча не спрашивать и не сохранять).
- **M-02**: «Что Ayla обо мне знает» — просмотр фактов с источником; удаление факта и «удалить всё» (C5, dual-system).
- **M-03**: запись из рекомендации в 2 тапа (наследует K-03; оплата опциональна — AYLA-DEC-0006).
- **M-04**: напоминание T−24h (R1).
- **M-05** [PM]: метрики §3 собираются (события уже есть: question shown/answered/skipped, context_used_in_recommendation).
- **M-06** [Legal]: правила инсайтов legal_reviewed; тексты consent/оферты — до конца недели 2 (риск PILOT_STREAMS §«Риски»).
- P1/P2 — наследовать из v1.0 с пометкой post-pilot.
