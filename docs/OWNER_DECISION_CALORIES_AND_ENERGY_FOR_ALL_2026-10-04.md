# Owner Decision 04.10.2026 — оценка калорий и расчёт энергопотребности доступны ВСЕМ (с точной областью)

**Пересматривает:** прежнее ограничение §7.1 для нутриции (02.10: гейт AI-калорий `BLOCKING_RESTRICTIONS={eating_disorder, minor}`; отказ `compute_norms` для `{pregnant, breastfeeding, eating_disorder}`+minor). Запись не редактирует прежние — замещает областью (см. [[owner-reversed-40-llm-calorie-estimation-now-allowed]], [[safety-records-are-superseded-never-edited]]).

## Решение (дословно по смыслу)
Сделать доступными **всем пользователям**: **(1) оценку калорийности еды** и **(2) расчёт персональной суточной потребности в энергии для ПОДДЕРЖАНИЯ**. 

**НЕ утверждено этим решением: (3) назначение дефицита/профицита и рекомендации по изменению веса** — остаётся НЕ универсальным (гейты сохраняются).

## Обязательные рамки реализации
- **НЕ реализовывать простым удалением `BLOCKING_RESTRICTIONS` и возвратом стандартного взрослого расчёта всем.** Три слоя раздельно (#1/#2/#3).
- **#2 — методики ПО ГРУППАМ, проверяемые:** взрослые / несовершеннолетние / беременность / кормление; отдельно РПП и заболевания. Mifflin-St Jeor валиден для взрослых, НЕ для детей/беременности/кормления. Где подходящей проверяемой методики нет — **явно обозначить пробел и предложить способ закрытия; НЕ генерировать норму свободным ответом LLM.** При недостатке данных — уточнять; при сбое — не выдавать выдуманное число.
- **Снять подавление разрешённого результата (#1/#2) во ВСЕХ местах:** backend (`compute_norms` отказ, гейт оценки), контекст и ответы бота (реактивный периметр `remarks_suppressed`), карточка, дневник, сводки, Mini App.
- **Различать:** автоматическое скрытие по признаку профиля (убрать для #1/#2) vs **выбранный самим пользователем режим «без чисел»** (сохранить — это выбор человека).
- «Доступно всем» = доступный КАЖДОМУ путь к ОБОСНОВАННОМУ результату (не «число любой ценой»).

## Что НЕ меняется
- #3 (дефицит/изменение веса) — гейты остаются (РПП/несовершеннолетние/беременность и пр. не получают назначение похудения).
- Оценка «Оценка ИИ» по-прежнему помечена, verified-first, не в сумме/цели (DRF-2761).
- Салоны/пилот — отдельный трек, идёт независимо.

## РЕШЕНИЯ ВЛАДЕЛЬЦА по 4 развилкам (04.10, окончательно)

1. **РПП × калорийность:** «для всех» ВКЛЮЧАЕТ РПП — **показ калорийности БЛЮДА (#1) доступен и при РПП** (зафиксировать пересмотр прежнего продуктового решения, НЕ переспрашивать). НО показ калорий блюда ≠ автоматическое назначение нормы. **Для РПП: #2/#3 — отдельный путь с участием специалиста, БЕЗ авто-дефицита и БЕЗ советов «компенсировать съеденное».** (NICE: при анорексии — нутри-консультирование в составе комплексного лечения.) Прежнее категоричное «любое калорийное число всегда вредно» — неверно, снять.
2. **Тумблер «без чисел» — НОВАЯ функция (завести).** Добровольное скрытие калорий, БЖУ и числовых целей на ВСЕХ экранах; управляет ОТОБРАЖЕНИЕМ, записи дневника сохраняет. (Прежняя формулировка «сохранить режим» была неточна — режима не было.)
3. **ИИ-оценки — ВКЛЮЧАТЬ в дневной итог** (иначе человек записал еду, а итог её не учёл). Условия: итог помечается «≈ … ккал, включая оценки ИИ»; источник каждой записи сохраняется; **справочное значение и оценка ИИ для одной порции НЕ складываются** (не дублировать); запись без значения НЕ считается нулём → итог помечается НЕПОЛНЫМ. (Пересматривает iv DRF-2761: раньше оценки в сумму не входили.)
4. **Недостающие данные — СОБИРАТЬ.** «Нужны данные» = промежуточное состояние с понятным вопросом. Сначала выбрать методику, затем обязательные поля: срок беременности, период/характер кормления, возраст, активность и пр. Официальный DRI учитывает возраст и беременность/лактацию — одной взрослой формулы мало. **Несовершеннолетние: обосновать возрастную методику EER с ВЕРСИЕЙ и границами применимости (проверяемо), НЕ выбирать название без проверки.**

## Порядок реализации (владелец)
1) единый расчёт + отображение калорийности еды (#1 для всех); 2) корректный дневной итог (оценки включены, помечены); параллельно 3) сбор данных + методики персональной потребности (#2 по группам). **Авто-назначение дефицита (#3) — отдельное решение, НЕ в этом.**

Лист реализации: DRF-2766.
